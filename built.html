Vintinuum — an AI system with a body, a memory and a world

Live
The largest thing here: 880 commits, 359 files, ~40 interactive surfaces.

A persistent AI platform I designed and built end to end. It has a 3D body rendered in WebGL, a memory system that survives restarts, a reasoning surface you can watch work, and a council of specialised AI agents that pick up tasks from a queue and complete them autonomously — writing code, reviewing it, and logging what they did. The interesting engineering problems were state persistence, agent coordination without deadlock, and keeping ~40 distinct front-end surfaces visually coherent.

What I'd point at in an interview

The agent system runs multiple Claude processes in parallel git worktrees so they never collide on the filesystem, with a lock-and-claim queue, dead-process detection that re-queues abandoned work, and an audited credential broker so no agent ever touches a raw secret. That last piece — deny-by-default, fail-closed, every access logged by name and outcome but never by value — is the part I'm proudest of.

The problems worth talking about

Anyone can list technologies. These are four things that actually broke, and what I did about them — which is the conversation I'd rather have in an interview.

Parallel agents, one filesystem

Running a dozen AI coding agents at once meant a dozen processes writing to the same repo. Instead of a mutex around everything, each agent gets its own git worktree — a real isolated checkout sharing one object store. They branch, commit and merge independently. Throughput went up with the agent count instead of collapsing under lock contention.

GIT INTERNALSCONCURRENCY

Secrets agents can use but never see

Autonomous agents needed API credentials; letting them read .env was not acceptable. I built a broker that injects a secret directly into a child process's environment, so the agent never handles plaintext. It's deny-by-default, fails closed on a malformed policy, and audits every access by name and outcome — never by value.

SECURITYLEAST PRIVILEGEAUDIT

A 530 that wasn't a DNS problem

Three domains started returning Cloudflare 530s. The instinct is to debug DNS and ingress rules — which would have wasted hours. The real cause: a tunnel can only serve a zone in the same Cloudflare account, and one tunnel had been created under the wrong one. The fix was three separate tunnels with three credential sets. I wrote it into the ops runbook so it can't cost anyone that afternoon twice.

NETWORKINGCLOUDFLARERUNBOOKS

Layout that can't collide, by construction

Floating UI panels kept landing on each other at small widths. Patching offsets one at a time never converges. The durable fix was structural: a single declared z-index ladder, panels that publish their measured edges as CSS variables so neighbours follow them instead of hard-coding a guess, and a layout where elements reserve space rather than overlay. This page is the extreme version — it has zero fixed-position elements, so collision is impossible rather than merely avoided.
